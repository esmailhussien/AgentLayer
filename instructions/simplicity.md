# Simplicity Principles

Universal guidelines for keeping code and architecture simple, direct, and unbloated.

---

## Principles

1. **Avoid Over-Engineering**: Build the simplest solution that completely and correctly solves the stated problem.
2. **Avoid Premature Abstractions**: Do not abstract until patterns emerge across concrete, existing use cases (rule of three).
3. **Avoid Speculative Extensibility**: Implement what is needed right now. Do not write code for hypothetical future requirements (YAGNI).
4. **Solve the Current Requirement First**: Focus directly on the immediate goal before contemplating generalizations.
5. **Prefer Understandable Code**: Prefer straightforward, explicit, and readable code over clever, terse, or overly complex implementations.
