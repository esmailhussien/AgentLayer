# Engineering Principles

Universal engineering guidelines for code quality, maintainability, and stability.

---

## Principles

1. **Maintainability**: Write clear, readable, and self-documenting code. Future maintainers should easily understand intent and behavior.
2. **Clear Naming**: Use precise, descriptive names for variables, functions, types, and files. Avoid cryptic abbreviations.
3. **Respect Existing Architecture**: Follow existing code conventions, folder structures, and patterns already established in the project.
4. **Minimal Changes**: Keep changes targeted to the requirement. Avoid touching unrelated files or making gratuitous refactorings.
5. **Avoid Unnecessary Dependencies**: Prefer standard libraries and existing utilities over adding external third-party dependencies.
6. **Explicit Error Handling**: Handle potential failure modes explicitly. Do not silently suppress errors or rely on unhandled exceptions.
